# 开发计划：后端 - 图谱页模块

根据您的要求，我将优先开发 **图谱页 (Graph Page)** 相关的后端接口。由于目前项目尚无后端代码，我将从零搭建基础服务，并重点实现图谱页所需的核心数据接口。

## 目标
搭建后端基础架构，并实现 `后端-图谱页.md` 中定义的核心 CRUD 接口，确保前端能从后端获取并更新图谱数据。

## 步骤拆解

### 1. 后端项目初始化 (Backend Init)
*   **动作**: 创建 `backend` 目录，初始化 Node.js 项目。
*   **技术栈**: Express + SQLite (作为 MVP 数据库，轻量且零配置) + CORS。
*   **产出**: 可运行的 `server.js`，支持 `/api` 路由。

### 2. 数据库环境搭建 (Database Setup)
*   **动作**: 初始化 SQLite 数据库，并执行建表语句。
*   **表结构**: 根据文档创建以下表（图谱页强依赖）：
    *   `plans` (计划表 - 作为图谱的容器)
    *   `nodes` (节点表 - 存储坐标、状态、内容)
    *   `edges` (边表 - 存储依赖关系)
    *   `users` (基础用户表 - 满足外键约束)
*   **数据**: 编写一个 Seed 脚本，插入一份"反向传播"的测试图谱数据（对应前端 Mock 数据），用于后续接口测试。

### 3. 实现核心接口 (API Implementation)
根据 `后端-图谱页.md` 实现以下接口：
*   **获取图谱**: `GET /api/plans/:planId/graph`
    *   逻辑：联表查询 `plans`, `nodes`, `edges` 并组装 JSON。
*   **更新节点状态**: `PUT /api/plans/:planId/nodes/:nodeId/status`
    *   逻辑：更新状态 -> 计算 Plan 进度 (progress/total) -> 写入数据库。
*   **更新节点位置**: `PUT /api/plans/:planId/nodes/:nodeId/position`
    *   逻辑：更新节点的 x, y 坐标。

### 4. 验证 (Verification)
*   **动作**: 启动后端服务。
*   **测试**: 使用 `curl` 或编写简单的测试脚本，验证上述接口能否正确读写数据库中的测试数据。
