## 检测并修复的问题

- 笔记生成保存失败时，`persistGeneratedNote` 原来会把错误继续抛到页面层，容易造成按钮状态异常或局部流程中断。现在保存失败会返回可恢复结果，不再让小错误扩散成页面崩溃。
- AI 解释和聊天总结保存笔记时，连续点击可能重复触发保存。现在增加了保存中的状态保护，同一个内容保存期间不会重复提交。
- 手动笔记保存失败时，原来可能直接抛错并清空用户正在编辑的状态。现在失败后保留编辑内容，避免用户输入丢失。
- 笔记删除失败时，原来存在未处理的 Promise rejection。现在删除失败不会导致整页异常。
- 笔记列表加载失败时，原来只显示失败提示。现在会优先回退到本地缓存，远程接口的小故障不会让笔记区完全不可用。
- 应用缺少顶层错误边界。现在新增全局 `AppErrorBoundary`，单个组件渲染错误不会直接白屏拖垮整个产品。
- 自动化脚本初版在 Windows PowerShell 5 下因为中文字符串编码解析不稳定。已改成 ASCII 脚本，避免测试工具本身成为不稳定源。
- Supabase 连接池耗尽、连接中断、短暂不可用、写入冲突、日期类型错误原来都会落到通用 500。现在统一映射为可恢复 JSON 错误，前端能拿到明确错误码，不会因为一个数据库异常打穿整个请求链路。
- 数据库连接原来只设置了连接超时。现在每个连接额外设置 `statement_timeout`、`lock_timeout`、`idle_in_transaction_session_timeout`，避免 Supabase 慢查询、锁等待或事务悬挂长期卡死请求。
- Phase 2 已补充前端失败隔离：API 层新增 `ApiError`，计划列表加载失败会回退本地缓存，图谱快照会持久化缓存，图谱加载失败时继续显示缓存，节点状态保存失败会恢复原状态。
- Supabase 集成测试夹具增加连接重试，稳定性脚本对真实 DB integration 增加一次自动重跑，降低 pooler 偶发断连对验收结果的影响。
